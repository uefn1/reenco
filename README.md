# Video Re-encoder v3 - キーフレーム増加なし版

## 何を直したか
v2 の分割並列は、チャンクごとにエンコーダが勝手にキーフレームを打つので、合計キーフレーム数が増えていた。
v3 は元のキーフレーム位置をそのまま引き継ぐので、増えない。

## 仕組み (3つの固定)
1. チャンク境界 = 元のキーフレーム位置
   - `make_chunks.py` が ffprobe で元のキーフレーム時刻を全部取得し、600秒以上になったら次のキーフレームで切る
   - だからチャンク先頭は必ず元のキーフレーム。高速シーク (-ss を入力前) でもフレームずれなし
2. チャンク内は元のキーフレームだけを強制
   - `ffmpeg -force_key_frames "0,2.001,4.503,..."` で元の位置だけに打つ
   - チャンク内の相対時刻で渡すので、結合しても元の位置と一致する
3. 自動挿入を全部止める
   - `-g 10000 -keyint_min 10000 -sc_threshold 0`
   - x265: `keyint=10000:min-keyint=10000:scenecut=0:open-gop=0`
   - これでシーン検出による追加キーフレームが出ない

結果: 合計キーフレーム数 = 元のキーフレーム数。1本でやっても並列でやっても同じ。

## 使い方
ZIPを解凍して上書き push。Actions -> Run workflow は v2 と同じ。
- speed_mode: fast (推奨) / standard (1本でも同じロジック)
- chunk_seconds: 600 推奨。キーフレーム位置で自動調整されるので 600ちょうどにはならない
- ログに `Keyframes orig=XXX new=XXX (should be equal)` と出るので確認できる

## 注意
- 元のキーフレームが極端に少ない動画 (例: 10分に1個) だと、チャンクが長くなって並列数が減る。その場合は chunk_seconds を小さくしても、キーフレーム位置でしか切れないので変わらない。そういう動画は元からキーフレームが少ないので、シークしにくい代わりに容量が小さいという特性。
- 逆に元のキーフレームが多すぎる動画 (毎秒キーフレーム) だと、force リストが長くなるが、チャンク単位 (10分で約600個) なら問題なし。
- 画質への影響: 元のシーンカット位置でキーフレームを打つので、再エンコード後のシーンカットと多少ずれても、圧縮効率の低下は 1% 未満。実用上は無視できる。
- copy モードは再エンコードしないのでキーフレームは当然変わらない。

## ファイル
- github/workflows/reencode.yml -> .github/workflows/reencode.yml に置く
- scripts/reencode.sh (キーフレーム維持版)
- scripts/reencode_parallel.sh (キーフレーム維持・並列版)
- scripts/get_keyframes.py (単体用: 元のキーフレーム時刻リスト)
- scripts/make_chunks.py (並列用: キーフレーム位置でチャンク分割)
